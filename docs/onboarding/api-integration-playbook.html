API 연동 프로세스 — Sales Playbook

초기 컨택부터 Go-Live까지, Sales가 알아야 할 9단계 End-to-End

CASE STUDY · Linkstay (China) 2025.06 ~ 2026.05 · 약 11개월 B2B Hotel Distribution · Supplier

개요 · 학습 목표

이 플레이북을 통해 ① 전체 프로세스 흐름(9단계, 각 단계 Sales 역할), ② 표준 조건과 협상 한도(Deposit·Credit·Settlement·Currency), ③ 계약서 단골 이슈 4대 대응법을 익힙니다.

🏢 Case Study — Linkstay

  • 국가: China · B2B Hotel Distribution
  • 채널: Ctrip · Fliggy · Meituan + WeChat 400K+ 에이전트
  • 계약 형태: Supplier (B2B Inventory 공급)
  • 일 주문량: 1,500 ~ 2,000건
  • 기간: 초기 컨택 → Go-Live 약 11개월

🎯 Sales = PM 모드

Sales는 9단계 전 과정의 프로젝트 매니저입니다. 단, 기술 구간은 고객사 IT ↔ OMH 개발팀 직접 소통이 원칙이며, Sales는 일정 관리·에스컬레이션을 담당합니다.

PHASE 1 Lead 발굴 & 초기 컨택

관심 → 계정 발급 → Follow-up까지

Sales 액션

  • ohmyhotel.biz 계정 발급 (임시 PW 포함)
  • 국가별 Top-Selling 호텔 리스트 공유 (KR/JP/VN)
  • 선불 결제 정책 안내 (Credit Card / Bank Transfer)
  • 응답 없을 시 정기 Follow-up (3~6주 간격)
  • 고객사 비즈니스 카운터파트 명확화 (R&D, Procurement)

Linkstay Case

  • 06.26 Jensen 계정 발급 + Top-Selling 송부
  • 06.27 Jason(Linkstay) 가격 검토 의사 + 계약서 요청
  • 07.30 Grace 첫 Follow-up (응답 없음)
  • 09.12 두 번째 Follow-up → 협력 의사 재확인
KEY LESSON · 응답이 없어도 포기 금지Linkstay는 첫 컨택 후 약 3개월 침묵(6월→9월) 끝에 재개되었습니다. 정기적 Follow-up이 결국 Deal로 이어집니다.
GATE ▸ Phase 2고객사 협력 의사 확인 + 진행 일정 공유 시점에 이동.

PHASE 2 NDA 발송 & 비즈니스 적합성 검토

비밀보장 확보 후 고객사 모델·채널 파악

  • 가격·재고·API 등 후속 자료는 NDA 체결 이후에만 공유

PHASE 5 API SPEC · DEV 환경 · DEV Key 제공

세일즈 요청 → 개발팀 발급 → 세일즈 → 고객사

Sales 액션 체크리스트

  • ① 개발팀에 DEV Credential 발급 요청 (Sales 기안)
  • ② API SPEC Site 링크 공유 (developer.ohmyhotel.com)
  • ③ DEV 환경 URL + DEV Key(Token·Secret) 전달
  • ④ 고객사 IT 담당자 명단 + 접속 IP 확보
  • ⑤ OMH 기술팀(@API SUPPORT) 채널 연결
  • ⑥ MS Teams 그룹 생성 → 이후 IT ↔ IT 직접 소통

고객사 전달 패키지

  • Signed Contract (양측 서명 PDF)
  • API SPEC Site — developer.ohmyhotel.com
  • DEV Environment — dev-api-ota-v2.ohmyhotel.com
  • DEV Credential Key (Token + Secret, 개발팀 발급)
  • Teams Channel (고객사 IT ↔ OMH 개발팀)

PHASE 6 테스트 시나리오 & 스테이징 테스트

시나리오 배포 → 스테이징 검증 → Cert 문서 제출

OMH 제공 자료

  • API Client Certification V2.1
  • Hotel Static Information (호텔·객실, 주 1회 갱신)
  • 스테이징 환경 + 테스트 호텔코드 (764481)
  • API 디버깅 지원 (Teams IT ↔ IT 실시간)

고객사 제출물

  • API Test Result + Log (6개 Request/Response 전량)
  • Certification Form (Client Detail·Support·접속 IP)
  • Voucher 스크린 캡처 (Payable by + Emergency contact)
  • Prior Acknowledgement 동의 (Static·매핑·MSP 등 6항목)
KEY · 소통 원칙고객사 IT ↔ OMH 개발팀 직접 소통이 기본. Sales는 일정 관리·에스컬레이션(PM 모드).
개선 과제테스트 시나리오는 현재 3종(Normal / 3rd include / Package rate) — 1종 통합이 개선 과제.

PHASE 7 ★ 테스트 완료 & Deposit 입금

라이브키 발급의 두 가지 전제 조건

  1. Cert 문서 + Log 수신 (고객사 IT → OMH 개발팀 직접 제출)
  2. 개발팀 내부 검증 (6개 API 응답 · Voucher 요건 충족 확인)
  3. 테스트 완료(Pass) 판정 — 미충족 항목은 재테스트
  4. Deposit 송금 요청 (지정 USD 계좌 · Bank Fee는 Party B 부담)
  5. 입금 확인 → 라이브키 발급 승인
★ AND 조건라이브키는 Cert Pass AND Deposit 입금, 두 조건 모두 충족 시에만 발급.
Linkstay 입금 사례USD 10,000 · Credit 1:1 · 통화 USD · Bank Fee 고객사 부담 · 송금일 2026.04.30 · 증빙 송금 영수증 PDF.

PHASE 8 Certification(라이브키) 발급 & Live Test

개발팀 → 세일즈 → 고객사 전달 + 실거래 검증

  1. 라이브키 발급 — Cert Pass + 입금 확인 후 PROD 자격증명 생성 (개발팀)
  2. 세일즈 경유 전달 — 개발팀 → 세일즈 → 고객사 (전달 이력 기록)
  3. PROD 적용 + 실거래 테스트 부킹 — 1건 이상 + 부킹번호 회신
  4. OMH 부킹 확인 → Go-Live 일정 공지 (ELLIS 기록 확인 후 D-Day 사전 통보)
Channel Information 교환 (양측)Channel BD · CS · Operation · Finance · IT 담당자 정보를 교환해 Go-Live 후 협업 라인을 확정합니다.

PHASE 9 ★ Go-Live / 라이브 완료

공식 런칭 + 초기 모니터링 + 셀스루 가속

A

Pre-Launch · D-7~D-1

Go-Live 날짜 공식 확정 · IT 모니터링 시프트 배정 · OP/CS 브리핑 · 인벤토리·요금 점검

B

Launch Day · D-Day

Live 채널 활성화(고객사 토글) · 개발팀·IT Teams 즉시 대응 대기

C

Post-Launch · D+1~D+30

주간 부킹/매출 공유 · 에러율·취소율 모니터링 · Top-Selling 보강 · 월간 정산 진입

Linkstay 실제 타임라인Cert 통과(4/29) → Deposit 입금(4/30) → 라이브키 발급 → Live Test(5/7) → 라이브 완료(5월 중) — 약 2주.

계약서 협상 단골 이슈 4선

고객사가 반복적으로 제기하는 조항 + 대응법

Q1 · 예약가로 체크인이 안 되는 경우 책임은?▸ SLA에 구체적 처리 절차 명문화(재예약·환불·차액 보전 등 시나리오별). 계약서 본문엔 'SLA에 따른다' 참조만.
Q2 · Party B 권리·의무는 API에만? 웹사이트도?▸ 요청대로 API 송출 범위에 한정 가능. 단, 우리측 웹사이트는 제외한다는 점 명시 (Linkstay 케이스 적용).
Q3 · 청구 분쟁 해결 5 working days로는 부족▸ 분쟁이 명시적으로 제기된 기간 1% Penalty 면제 단서 추가. 최대 10 working days까지 연장 가능.
Q4 · 1% Daily Payment Penalty가 과도▸ 분쟁 기간 면제 단서 + Cap(예: 누적 30%) 조항 협상 가능. 기본률 인하는 양보 불가.
